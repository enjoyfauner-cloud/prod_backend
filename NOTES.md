## Решения
- Монолит FastAPI, три слоя (api → services → db). Расчёт сделан чистой функцией без БД и часов, отсюда тестируемость и воспроизводимость.
- Условия версионируются (`card_terms`: version, valid_from, valid_to (включительно), checked_at). Импорт запрещает пересечение периодов у одной карты.
- Базовый кэшбэк хранится как правило категории `other`. Запрос по самой категории `other` использует базовую ставку без `fallback_reason`.
- `min_purchase` для категории не выполнен → откат на `other` (с `fallback_reason`).
- Лимиты только по правилу (карта × категория). Общий лимит на карту не моделируем.
- Деньги: `Decimal` / `NUMERIC`, в JSON строкой. Округление **вниз до копейки** (`app/money.py`) один раз, после лимита. `effective_rate_percent` тоже вниз.
- Тай-брейк: кэшбэк ↓ → остаток лимита после покупки ↓ (без лимита выше) → valid_to ↓ (бессрочно выше) → card.code ↑.
- Публичный id карты = строковый slug (`cards.code`). **Идентичность карты при импорте = code** (после ревью; раньше была пара (банк, название)). Переименование или перенос в другой банк обновляет ту же строку, ссылки «моих карт» не теряются. Пара (банк, название) остаётся уникальной, конфликт даёт понятную CatalogImportError.
- Импорт: для каждой карты из файла её версии и правила приводятся точно к файлу (лишние версии удаляются, после ревью), поэтому пересечение периодов в БД невозможно. Карты, которых нет в файле, НЕ удаляются.
- `as_of` необязательный, по умолчанию «сегодня» в Europe/Moscow. Это единственное место, где читается текущее время (`api/deps.today`).
- Истёкшие условия → список `outdated` (rank = null), никогда не попадают в top/eligible. Карты только с будущими условиями считаются неподходящими.
- Неподходящие карты → только `not_eligible_count`.
- Использованный лимит хранится по месяцам (`period` YYYY-MM) и учитывается только в `scope=my`. Применяется к категории сработавшего правила (если сработал откат на `other`, берётся использование по `other`).
- `DELETE /me/cards/{id}` удаляет и данные об использовании.
- Пользователь = анонимный UUID в `X-User-Id`. Реквизитов нет, схемы запросов запрещают лишние поля (`extra=forbid`).
- `promo_url` не участвует в ранжировании (есть тест).
- Максимальная сумма 10 000 000 ₽, не больше 2 знаков после запятой.
- Сообщения валидации переведены на русский (`app/errors.py`).
- БД недоступна (OperationalError/InterfaceError/invalidated connection/OSError) → 503 `service_unavailable`. Прочие ошибки БД (IntegrityError, ProgrammingError) → 500, это баги (после ревью). `/health` не трогает БД, `/ready` проверяет `SELECT 1` и считается в `app_errors_total`.
- Классификация ошибок БД: 503, если OperationalError/InterfaceError/invalidated или SQLSTATE класса 08/53/57, а также при таймауте пула SQLAlchemy и сетевом OSError (отказ, DNS, таймаут, «Multiple exceptions»). FileNotFoundError, PermissionError, IntegrityError → 500.
- Уникальность (банк, название) карты: DEFERRABLE INITIALLY DEFERRED (миграция 0002). Импорт в конце делает `SET CONSTRAINTS ALL IMMEDIATE` и превращает конфликт в CatalogImportError.
- CLI: битый файл или нарушение ограничений данными → код 2; недоступная БД → код 3.
- `GET /cards?category=` ищет категорию в той же версии условий, что показывается (действующая, иначе последняя истёкшая).
- Миграции выполняет отдельный контейнер `migrate` (затем идемпотентный импорт демо). API стартует только после его успеха.
- Postgres на хосте слушает порт **5433** (5432 на ноутбуке занят). Меняется через `POSTGRES_HOST_PORT`.
- Логи: Alloy собирает stdout контейнеров проекта → Loki (хранение 7 дней). Метки: service, level; request_id идёт как structured metadata.
- Telegram-контакт: шаблон + entrypoint.sh подставляют токен как строку (Grafana 11 ломается на числовом chat_id из $VAR).
- Grafana на порту 3001 (3000 оставлен фронтенду).
- Метрики с метками по шаблону роута (не по URL), `/metrics` в метрики не пишется.
- Внешний error-tracker (Sentry) не подключён: ошибки видны в JSON-логе со стеком и request_id, в метрике `app_errors_total` и в алерте доли 5xx.
- Зависимости только из заявленного стека: fastapi, uvicorn, pydantic(-settings), SQLAlchemy, asyncpg (драйвер Postgres для async), alembic, prometheus-client; dev: pytest, pytest-asyncio (async-тесты), httpx, ruff, pyright.
- Папку `hello_world/` (шаблон IDE) не трогаем, она исключена из линтера.
- PyCharm может подсвечивать импорты `app.*` как неразрешённые: корень проекта в IDE выше папки `prod_backend`. Pyright из CLI (`make typecheck`) показывает 0 ошибок.
